Why the sandbox run stops at awaiting_payer

A freshly created PayPal order is CREATED, not approved. Capturing it returns 422 UNPROCESSABLE_ENTITY / ORDER_NOT_APPROVED, which is why this code now returns the approval link instead of assuming capture is legal. The real flow is: create order, hand the payer the payer-action link, capture after approval (--capture-order). The fixture run models a payer who already approved, which is the only way to exercise the capture path offline.
