What the live runs changed in the code

1. Capture needs approval. A wallet order comes back CREATED and capture returns 422 ORDER_NOT_APPROVED, so the agent now stops at awaiting_payer and hands back the payer-action link.
2. payment_source needs an idempotency key. Posting a card without PayPal-Request-Id returns 400 PAYPAL_REQUEST_ID_REQUIRED.
3. Cards settle at creation. A card order returns COMPLETED from POST /orders, and a second capture is rejected with 422 ORDER_ALREADY_CAPTURED, so the agent treats that status as done and skips capture.

Reproduce

npm install && npm run build

# live card settlement
PAYPAL_CLIENT_ID=... PAYPAL_CLIENT_SECRET=... PAYPAL_TEST_CARD=4111111111111111 \
  npm run cli -- --amount 1.00 --merchant "Sandbox Coffee Co" --card

# live wallet order (needs a human to approve, then --capture-order)
PAYPAL_CLIENT_ID=... PAYPAL_CLIENT_SECRET=... npm run cli -- --amount 1.00

# offline fixture
node scripts/contract-server.mjs --port 8899 --auto-approve
PAYPAL_CLIENT_ID=contract-client PAYPAL_CLIENT_SECRET=contract-secret \
  PAYPAL_BASE_URL=http://127.0.0.1:8899 npm run cli -- --amount 12.50
